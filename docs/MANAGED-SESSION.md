# Managed sessions

`Session` owns secure enrollment, the listener and allocated port, a persistent mDNS browser and advertisement, trust, automatic exchanges, cancellation, and encrypted local records. The low-level `Engine` remains available for legacy integrations. Managed sessions reject legacy linking and sync messages.

Run `cargo run -p libresync --example managed_two_peers` for two real localhost sessions, automatic first/edit/resume synchronization, and explicit application processing receipts. The demo uses temporary development keys and data. Platform apps should implement `KeyStore` with their secure store.

## Configure and open

Supply `SessionConfig::new(private_state_directory, DeviceMetadata)` with a stable app ID, display names, schema version, and complete adapter descriptors. Matching app IDs alone do not establish schema compatibility. Every descriptor must be transactional. `SessionConfig::with_adapter` registers application validation and merge policy; the registered descriptor must exactly match the manifest.

`Session::open(config, Arc<dyn KeyStore>)` is fallible. An OS-held exclusive lease prevents concurrent writers to the same directory and is released on process exit. Identity, certificate, private key, and a separate stable storage key occupy one namespaced secure-store item. A missing, incomplete, malformed, or unavailable identity beside existing data fails; it never creates a replacement identity. Transport group keys live in the encrypted journal and cannot make old recovery snapshots unreadable when joining a group.

`start` is idempotent and returns the allocated address. `pause`, `resume`, `shutdown`, and dropping the session preserve local records. Lifecycle operations persist generation fences, cancel sockets, and join listener, discovery, scheduler, and inbound workers. Rust operations can perform IO and block: native SDKs dispatch them to IO workers.

## Connect devices

`create_invitation(ttl)` returns a secret-bearing `SessionInvitation` containing the inviter identity, pinned certificate, full app manifest, and connection endpoints. Encode it for a QR code or deep link; never log the credential. The joining app calls `connect(&invitation)`, without manually wiring IP addresses or TLS options.

For a named discovery list, use `discovered_peers()`. Advertisements are untrusted hints. `create_code_invitation(ttl)` opens code entry; `connect_code(&discovered_peer, code)` handles descriptor construction, endpoint selection, compatibility checks, and authenticated exchange. Secrets never enter mDNS. `close_pairing` closes invitations and updates the advertisement. Invitations expire, are single-use, have bounded attempts, and do not reopen after restart. Startup reconciles interrupted authenticated enrollment against the exact durable identity/certificate/invitation journal; it cannot revive a revoked peer.

An enrolled group refuses an implicit transport-key replacement. A changed certificate pauses the affected peer. `repair_peer(device_id, &new_pinned_invitation)` explicitly authorizes that replacement; failed repair leaves the revocation tombstone and local data intact. `pause_peer`/`resume_peer` control exchanges. `remove_peer` durably revokes the identity, cancels current workers and queued exchanges, and preserves local records. Existing remote copies and a previously learned group key cannot be remotely erased.

## Records and atomic merge

Managed adapters operate on **Session-owned logical records**. Their `inspect`, `export`, `preview`, `prepare`, `commit`, and `recover` hooks are pure validation/model operations. They must not modify an external file or database. LibreSync does not claim a transaction across arbitrary external app stores, and the legacy whole-file `JsonFileAdapter` cannot be registered here.

The default `RecordsAdapter` merges by Lamport clock and retains tombstones. Custom policies can reject immutable op collisions, validate payloads, and define domain merges. Export policy can return unchanged selected records or a subset; it cannot invent clocks or transform a selected payload. Prepared changes are serializable. The coordinator validates all adapters before publication, saves the prepared transaction and recovery data atomically, saves the completed journal, and only then acknowledges storage. Restart validates and completes a prepared transaction before enabling network work.

An authoritative empty first snapshot can import automatically. When both devices already have records, incoming candidates remain encrypted and staged. `bootstrap_preview(peer_id)` binds a token to the authenticated fingerprint, source epoch/sequence, exact candidate records, and the local revision across adapters. `resolve_bootstrap(preview, Merge)` revalidates these bindings and applies the app's merge policy; any newer local or remote candidate makes old consent stale. `Cancel` preserves data and the source cursor and pauses that peer. No preview receipt clears the sender's pending changes. `recovery_snapshots()` exposes the encrypted journal's pre-merge local models for application-managed recovery.

`set(adapter, id, bytes)` and `delete(adapter, id)` are coordinator mutations. Deletion produces a durable tombstone. Local edits wake a debounced scheduler; periodic catch-up, bounded retry backoff, address rediscovery, and explicit `wake()` handle reconnect and platform resume. Retry deadlines operate independently of the catch-up period.

## Truthful status and app processing

`snapshot()` distinguishes local edit revision, actual per-peer pending exported records, transmitted checkpoints, remote `stored` receipts, remote `applied` receipts, locally `received` checkpoints, and locally `processed` checkpoints. Receipts name exact history epochs and captured export sequences. A local edit after export remains pending; an unrelated inbound change cannot clear it. Offline peers are waiting. Paused/stopped sessions retain receipt evidence without claiming current synchronization success.

The managed inbox is **Stored** until the application acknowledges processing. Use `application_inbox()` to atomically capture records and their per-source receipts, commit those records in the app's transaction, then call `acknowledge_inbox(&captured_inbox)`. An older captured receipt can advance cumulative processing but cannot acknowledge or clear newer incoming data. `acknowledge_applied(peer, &receipt)` is available when the app already holds an exact checkpoint; read the receipt and records coherently. Store-and-forward applications leave application acknowledgment unset until real processing occurs.

Subscribe to bounded `SessionEvent` observation and read snapshots as authoritative state. Recent diagnostics remain in the snapshot even when an event consumer falls behind. Errors include typed managed codes, evidence, and supported actions. `report_platform_evidence` accepts Allowed, Denied, or Unknown callbacks from the platform SDK; empty discovery never proves a permission denial. Typed validation, compatibility, group, and storage failures retain their evidence and corresponding actions; unspecified I/O and protocol failures remain Unknown rather than asserting a connectivity cause.

A failed fsync/rename can leave the disk commit outcome uncertain. The session enters Failed, publishes no failed candidate or receipt, and refuses further mutations. Close and reopen to reconcile the prepared journal. Do not reinterpret secure-store errors as absence or claim that an operation definitely rolled back after an uncertain storage error.

The state-directory lease uses the Rust standard library file-lock API and requires Rust 1.89 or later.

Managed discovery retains one browser for the runtime lifetime. The mDNS dependency implements RFC 6762 multicast rate limiting and excludes macOS point-to-point and Apple peer-to-peer interfaces by default, avoiding discovery traffic that can starve concurrent local TLS handshakes. IPv6 discovery retains the interface scope needed to connect to link-local addresses.

Shutdown cancels every tracked socket and joins all runtime workers even if a worker panics. It awaits discovery daemon shutdown and returns accumulated cleanup failures only after the remaining resources have been released.

Managed record values and encrypted batch bytes use bounded base64 JSON. Each record permits up to 64 MiB, including a serialized 32 MiB compressed application snapshot. The complete authoritative export, including metadata and receipt proof, must fit 128 MiB before encryption; the existing 256 MiB outer protocol frame cap is unchanged. Local edits, inbound merges, and recovered prepared candidates that exceed this budget fail before publication and preserve data and cursors. These are whole-state bounds; applications must partition or compact larger models before committing them.

Exact checkpoint receipts carry a 32-byte HMAC proof minted only at export. A purpose-separated HKDF key binds the application domain, full enrolled peer identity, certificate fingerprint, durable enrollment incarnation, source epoch, and sequence using length-prefixed encoding. Constant-time verification accepts legitimately delayed receipts across ordinary restart while removal, repair, and fresh enrollment rotate the incarnation. Invalid cursor hints trigger an authoritative full export; stale processing proofs cannot advance Applied and do not prevent recovery. No growing issued-checkpoint history is retained.

`SessionConfig.authenticated_io_timeout` defaults to 60 seconds and must be nonzero and no greater than five minutes. It bounds idle transfer/commit I/O after exact enrollment and certificate authentication; initial TLS, the bounded first message, and unauthenticated pairing retain short deadlines. Stop cancels registered sockets and joins workers, including connections registered while durable coordinator work is blocked. Large debug-build cryptography can require a larger configured budget; cancellation and generation checks still fence publication.

The dedicated near-limit delivery gate exercises a 64 MiB record plus a 31 MiB record over real TLS and verifies Stored then Applied. Run `cargo test -p libresync --release --all-features --locked compact_64_mib_record_and_near_aggregate_limit_cross_real_tls -- --ignored --nocapture`. The optimized fixture uses the production 60-second authenticated budget; an explicitly run debug fixture allows 180 seconds for unoptimized cryptography. Run the same command with filter `compact_32_mib_snapshot_crosses_real_tls_and_aggregate_overflow_is_atomic` for the 32 MiB delivery and application receipt gate. Ordinary tests retain smaller real TLS exchanges, 64 MiB serialization edges, and atomic aggregate overflow checks.

Pairing protocol version 2 separates authentication from durable preparation. The joiner promptly sends `PairConfirm` after verifying the server challenge. The inviter verifies it under the short initial deadline and immediately returns `PairReady`, authenticated with its separate transcript-derived ready key, without committing enrollment or releasing the app key. The joiner verifies Ready, extends only its authenticated I/O budget, durably prepares its challenge journal, and sends `PairPrepared` authenticated with the distinct prepared key. Only after verifying Prepared may the inviter commit and send the authoritative key. Missing, reflected, wrong, and replayed preparation tags cannot enroll a peer. The inviter extends its budget only after verified client proof. Version 1 is rejected explicitly; legacy Engine exchange is unchanged.

The populated pairing gate runs both a 32 MiB inviter and a 32 MiB joiner with unchanged short initial deadlines and the production authenticated budget: `cargo test -p libresync --release --all-features --locked populated_32_mib_inviter_and_joiner_pair_with_short_initial_deadlines -- --ignored --nocapture`.
