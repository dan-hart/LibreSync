# Momentum managed integration

Momentum at source commit `766064bfa340a391d6a9465b60a030e1dc0c9f95`
uses the legacy `P2p`/`Engine` path dependency. That client cannot silently connect
to managed AlwaysOn pairing. This change provides an **opt-in transport module**
and verified migration patch; it does not switch the existing Momentum UI,
UniFFI/native APIs or runtime automatically.

## Exact app policy

`momentum_manifest()` declares app/namespace `io.github.dan_hart.Momentum`,
schema version `1`, adapter `ops`, schema `momentum`, and pure transactions.
`MomentumAdapter` stores the full serialized `SyncRecord` inside a managed logical
record. Record keys include namespace/schema/entity/ID. Original record and field
clocks, opaque fields, timestamps and tombstones remain intact.

Entities are immutable unique-ID `Op` records with `t`, `origin`, `op` and
`action`, and `Snapshot/latest` with `t`, `origin` and `gz_b64`. Unequal live
operation payloads at the same ID are rejected regardless of a newer clock.
Valid later app-issued operation tombstones are accepted and cannot be resurrected
by an older operation. A companion does not reproduce the legacy adapter’s
age-based operation compaction.

Gzip snapshots are limited to 32 MiB compressed and 128 MiB expanded, with
bounded decompression. Core 64 MiB record and 128 MiB full-batch budgets remain
in force. A maximum compressed snapshot’s base64/JSON envelope fits the single
record bound but multiple records may exceed the aggregate budget.

## Review and verify the opt-in patch

The patch at `examples/momentum-migration/managed.patch` adds a `managed` feature,
`sp_p2p::managed::ManagedMomentum`, and a real Momentum integration test against
the exact source commit. `managed.rs` and `managed-tests.rs` are readable source
copies beside it. Point Momentum’s existing `libresync-src` path dependency at
the managed-capable LibreSync release when integrating; the patch does not fetch
or replace the SDK checkout by itself.

```sh
CARGO_TARGET_DIR=/tmp/momentum-managed-build \
  ./scripts/examples/verify-momentum-migration.sh /path/to/momentum
```

The verifier creates an isolated `git archive` of the pinned commit, checks and
applies the patch, links only that temporary tree to this SDK, and runs the actual
`sp-p2p` test. It does not change the Momentum repository. The test publishes a
real `Action::AddTask`/`Op`, builds full `AppData::fresh` plus operation replay,
validates the received snapshot with `AppData::from_backup`, saves it durably,
and issues **Applied** only after the application transaction. Existing legacy
transport APIs remain compiled and available.

## Integrate the app runtime explicitly

1. Back up the old Momentum app store, `p2p` journal/state, and its existing secure
   keys. Stop the old P2p runtime before enabling the new one.
2. Open `ManagedMomentum` in a **new managed directory**, using Momentum’s secure
   KeyStore and friendly device name. Start its Session and expose its typed
   state, discovery, invitations, merge preview/consent and repair APIs in the
   app’s native interface. Legacy devices need a new managed invitation.
3. Re-publish current outgoing operations and a snapshot of the committed app
   store. If importing an explicit copy from a legacy `RecordView`, use
   `import_legacy_copy` to preserve wire clocks/tombstones. It imports no old
   trust, group keys, enrollment, receipts, or automatic approval.
4. Capture `ManagedInbox`, validate/replay its operations and bootstrap snapshot
   under Momentum’s existing durable `try_edit_checked` transaction, and keep
   exact operation IDs in that transaction for idempotent retries. Do not reuse
   the legacy inbox acknowledgment, and do not clear applied-ID receipts merely
   because all live records remain retained in the managed Session.
5. Call `acknowledge_committed(&captured_inbox)` only after that durable transaction
   succeeds. Keep the entire captured checkpoint/proofs; a failed transaction
   or failed acknowledgment must leave records available for retry. Avoid
   acknowledging a newer inbox than the app actually saved.

The transport patch deliberately leaves snapshot/merge consent and full native
runtime wiring as an app integration task. Its app-facing inbox preserves
source-issued receipt evidence and provides decoded real Momentum operation and
snapshot types. A generic backup rollback is not an operation-log recovery plan.

## Fixture provenance and acceptance

`crates/libresync/tests/fixtures/momentum-766064b.json` was generated by the real
private `sp-p2p::OpAdapter::load_records` in an isolated archive of the pinned
commit. It contains a live real AddTask operation, an actual age-derived
operation tombstone and `Snapshot/latest`. The snapshot is a full fresh AppData
with AddTask replay, validated through `AppData::from_backup`, not invented
minimal JSON. Generation changed only the temporary test module; no primary
Momentum files were edited. IDs/timestamps are fixed once in this public test
fixture and describe synthetic sample data.

Companion acceptance tests exercise exact fixture preservation, immutable
collisions, tombstones and size bounds, producer → durable companion Stored →
producer disconnect → companion restart → second app delivery → app Applied,
plus independent different-app spaces and rejected unregistered contracts.
The separately applied patch test verifies the current real Momentum model and
operation codec. Neither test claims physical-device/native UI integration or
that the unmodified legacy Momentum client is already compatible.
