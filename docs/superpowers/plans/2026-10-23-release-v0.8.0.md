# LibreSync v0.8.0 release plan

> For agentic workers: use superpowers:subagent-driven-development for metadata and independent spec/quality review. Execute publication only after frozen-source and artifact verification.

**Goal:** Publish immutable v0.8.0 native SDK assets so apps can opt into Nearby Sync through the Git Swift package or downloaded Android Maven repository.

**Architecture:** Release merged native Nearby Sync without modifying consumer apps. Build binaries from committed versioned source, generate the root Swift manifest from final asset bytes, pass exact-head candidate and merged-main CI, then tag and publish those exact bytes.

**Tech stack:** Rust, SwiftPM/Xcode, Android Gradle/JNI, GitHub Releases, Homebrew.

## 1. Prepare versioned source

- [x] Align all four crate manifests/dependencies, both Cargo locks, nested Tauri manifest/config, and Android core/Compose/sample metadata to 0.8.0.
- [x] Move Unreleased entries into a dated 0.8.0 changelog section; write RELEASES.md notes and update current-version install docs/README while preserving historical versions and pinned integrations.
- [x] Review metadata against docs/RELEASING.md, then commit the native-source snapshot. Root Package.swift is generated later from exact binary bytes.

## 2. Build and validate artifacts

- [x] Run scripts/package-native-sdk.sh 0.8.0 OUTPUT with matched rustup compiler/targets, explicit Android SDK/JDK, and ignored output paths.
- [x] Copy OUTPUT/Package.release.swift to root Package.swift. Run exact-byte release-readiness and security audits; verify every ZIP/AAR license, five Apple slices, both Android ELF alignments and versioned Maven publications.
- [x] Run source Swift SDK and Mac demo tests and generic iOS compilation. Extract final Swift/Maven archives into fresh directories and compile real consumers; run Android JNI tests on actual API37/16 KiB emulator (local ARM64 plus hosted x86_64 CI).
- [x] Record sanitized source commit/inventory, compiler versions, commands, hashes, and evidence limits in release provenance. Do not log or package keys, profiles, private notes, or state.

## 3. Review and source publication

- [x] Independent specification review of frozen source/artifacts, then separate quality/security review. Address confirmed issues and rebuild any affected binaries before recalculating hashes.
- [ ] Commit the exact-byte root manifest and release metadata; push release branch and create a PR. Wait for all four CI jobs on the exact final head, merge, and wait for merged-main CI. Do not weaken checks. The four jobs must cover the full Rust/audit/coverage/AlwaysOn/Apple/Android matrix in docs/RELEASING.md.

## 4. Immutable release and consumer verification

- [ ] Compare merged main with the binary-source commit: only reviewed manifest/release-metadata changes may differ. Rebuild and repeat review/verification if any Rust, packaged Swift/Kotlin, build-script or packaging inputs change.
- [ ] Create/push immutable v0.8.0 tag on verified merged main. Publish GitHub release with the exact SDK archives, AARs, C header/schema, Package.release.swift, SHA256SUMS, and provenance.
- [ ] Verify GitHub tag/release target and server-side digests against local final bytes. Build a fresh remote Git Swift consumer at exact 0.8.0 using LibreSyncSessionModel and LibreSyncNearbySyncView; compile generic iOS against the published SDK.
- [ ] Update existing Homebrew formula to verified v0.8.0 tag archive/checksum, run style/tagged-source CLI verification, publish and read back tap state. Preserve unrelated tap changes.
- [ ] Fast-forward clean primary LibreSync checkout after publication. Report install coordinates and verification limits, including physical iPhone privacy/camera, physical Android hardware, human usability, actual Finder/Dock reopen, and GUI signing limits.
