# Managed C ABI v1

Managed Session is separate from legacy Engine ABI v2. `libresync_managed_abi_version()` returns 1. Configuration, commands, compact records, proof-bearing inbox receipts and per-call typed result/error envelopes are defined in `bindings/managed-v1.schema.json`. C declarations and ownership rules are in `bindings/include/libresync.h`.

`libresync_session_open(config, callbacks)` transfers callback context ownership even if creation fails and returns `{"abi":1,"ok":true,"value":<uint64 handle>}`. Failures return `{"abi":1,"ok":false,"error":{"code":"...","message":"..."}}`. Every returned string is independently owned and must be freed once with `libresync_string_free`. Managed APIs do not use legacy thread-local last_error.

Handles are monotonically allocated registry IDs, never dereferenced pointers. Calls acquire an Arc under the registry lock and release that lock before doing work. Close removes the ID first, cancels/shuts down core work, and preserves any already acquired handle until that call returns. Repeated close is safe; new calls to a removed handle return Closed. IDs are never recycled and exhaustion fails with Busy.

Secure-storage callbacks may run on any native worker. They must be thread safe and must not reenter LibreSync. Operations are get=0, set=1, delete=2; return 0 for success, 1 for genuinely absent get only, and -1 for unavailable/corrupt/error. Getter output remains callback-owned until release_buffer; core copies at most 1 MiB and invokes release_buffer exactly once for every non-null callback result. Context remains owned by the handle until all acquired calls finish, then release_context runs exactly once. Never return absent for locked or unreadable storage.

Commands cover start/shutdown/pause/resume/wake, records/set/delete/get/import, coherent inbox/acknowledge, invitation/code/connect, discovery/repair/remove, bootstrap preview/resolve, recovery/prune, diagnostics/evidence and bounded event polling. Receipt proof bytes are source-issued opaque evidence; preserve them verbatim. Never acknowledge Applied before the app durably stores the matching records and receipts together.

The default authenticated IO timeout is 60 seconds, greater than zero and at most five minutes. Records are bounded to 64 MiB; the complete serialized authoritative batch and C request are bounded to 128 MiB. Violations return InvalidRecord before publication. Unsupported invitation versions are identified before strict invitation decoding and return upgrade guidance.

Policy selection is explicit: notes and momentum use exact verified companion manifests; records accepts a caller's stable custom app/namespace only for transactional logical-records-v1 descriptors. Unsupported custom policies are refused, not treated as arbitrary LWW. Policies are pure; Session owns journal storage.

Platform Bonjour hooks return the real listener port and reviewed public TXT, with no QR secret or code. Bounded untrusted hints feed existing pinned TLS/schema authentication and reconnect scheduling. IPv4 listeners filter IPv6 addresses. A withdrawn hint removes only discovery presence, retaining enrollment/data. Expired/closed invitations disappear from returned TXT. Discovery does not authorize trust.

`subscribe` returns an independent queue ID (maximum 64 per Session); pass it as `subscription` to `events`, then `unsubscribe` on teardown. Close discards all queues. Unsubscribe fences new polls; an already acquired poll completes within its bounded timeout. The legacy default poll queue remains available. Event polling drains at most 256 events and blocks at most one second. Observation cancellation need not cancel shared network work. `cancel` interrupts currently registered core IO; scheduler retry remains possible. `pause` sustains suspension; `close` invalidates future acquisition. Native wrappers keep cleanup awaitable across concurrent close callers.

After durably saving the complete coherent inbox, acknowledgement sends only its captured revision and exact source receipt map; record bytes stay in the saved app transaction and are not retransmitted in the acknowledgement request. This keeps a near-limit valid record aggregate acknowledgeable even with multiple proof-bearing source receipts. The C command accepts an optional legacy `records` field but does not use it. Cancellation before a queued Swift call starts prevents native work; cancellation after start interrupts current IO on a best-effort basis and is not transaction rollback.

## Portable identity migration

Version 0.8.1 adds an optional `legacy_identity_key` open-configuration field and typed `IdentityMigrationRequired` / `IdentityCandidateMismatch` errors without changing managed ABI v1 function signatures. A candidate must be an exact `managed-<64 lowercase hexadecimal characters>-identity-v1` account name. It is accepted only when an existing regular encrypted journal has no identity reference; it cannot create a new installation or override an existing reference. The core authenticates the journal and validates its identity/manifest before persisting a reference to the existing account. Missing or wrong candidates never create keys or erase state.

Ordinary opens need no new field. Native Swift Keychain migration supplies candidates internally from bounded exact-service account metadata; custom C/Rust stores must provide their own reviewed legacy migration strategy. Preserve `identity-ref.json` alongside `session.enc` on subsequent moves. Storage errors, corruption and missing referenced keys fail closed.
